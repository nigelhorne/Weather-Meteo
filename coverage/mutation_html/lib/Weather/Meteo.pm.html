  101: =head1 SYNOPSIS
  102: 
  103: The C<Weather::Meteo> module provides an interface to the Open-Meteo API for retrieving
  104: historical weather data from 1940 and weather forecasts up to 16 days ahead.
  105: It allows users to fetch weather information by specifying latitude, longitude, and a date.
  106: The module supports object-oriented usage and allows customisation of the HTTP user agent.
  107: 
  108:       use Weather::Meteo;
  109: 
  110:       my $meteo = Weather::Meteo->new();
  111: 
  112:       # Historical weather
  113:       my $weather = $meteo->weather({ latitude => 0.1, longitude => 0.2, date => '2022-12-25' });
  114: 
  115:       # Forecast (default 7 days)
  116:       my $forecast = $meteo->forecast({ latitude => 51.34, longitude => 1.42 });
  117: 
  118:       # Sunrise and sunset for a specific date
  119:       my $times = $meteo->sunrise_sunset({ latitude => 51.34, longitude => 1.42, date => '2025-06-21' });
  120:       print "Sunrise: $times->{sunrise}\n";
  121: 
  122:       # Retry transient API failures up to 5 times, starting with a 2 second delay
  123:       my $patient = Weather::Meteo->new(max_retries => 5, retry_delay => 2);
  124: 
  125:       # Reword or translate the warnings and errors
  126:       my $french = Weather::Meteo->new(messages => {
  127:           not_a_date => "'{date}' n'est pas une date valide",
  128:       });

  130: =over 4
  131: 
  132: =item * Caching
  133: 
  134: Identical requests are cached (using L<CHI> or a user-supplied caching object),
  135: reducing the number of HTTP requests to the API and speeding up repeated queries.
  136: 
  137: When a request is made,
  138: a cache key is constructed from the coordinates, date, and timezone.
  139: If a cached response exists it is returned immediately,
  140: avoiding unnecessary API calls.
  141: 
  142: =item * Rate-Limiting
  143: 
  144: A minimum interval between successive API calls can be enforced to ensure that the
  145: API is not overwhelmed and to comply with any request throttling requirements.
  146: 
  147: Rate-limiting is implemented using L<Time::HiRes>.
  148: A minimum interval between API calls can be specified via the C<min_interval> parameter
  149: in the constructor.
  150: Before making an API call,
  151: the module checks how much time has elapsed since the last request and,
  152: if necessary,
  153: sleeps for the remaining time.

 1372: =head1 LIMITATIONS
 1373: 
 1374: =over 4
 1375: 
 1376: =item * Archive data lag
 1377: 
 1378: The Open-Meteo archive endpoint has a lag of approximately five days before
 1379: recent historical data becomes available.
 1380: For dates within the past five days,
 1381: C<weather()> may return C<undef> even when no error occurs.
 1382: Use C<forecast()> or C<sunrise_sunset()> (without a date) to obtain data for
 1383: today or recent days.
 1384: 
 1385: =item * Coordinate range
 1386: 
 1387: The module normalises coordinates with a bare leading decimal point (e.g.
 1388: C<".5"> to C<"0.5">) but does not validate that latitude is within C<-90..90>
 1389: or longitude within C<-180..180>.
 1390: Out-of-range values are passed to the API, which may return an error.
 1391: 
 1392: =item * No sub-hourly resolution
 1393: 
 1394: The hourly data arrays always contain exactly 24 entries per day (one per hour).
 1395: Sub-hourly resolution is not supported by this interface.
 1396: 
 1397: =item * Per-process rate limiting
 1398: 
 1399: The C<min_interval> rate limiter tracks the last request timestamp within a
 1400: single process instance.
 1401: Multiple concurrent processes or threads are not coordinated and may collectively
 1402: exceed the desired request rate.
 1403: 
 1404: =item * Timezone resolution requires an API key
 1405: 
 1406: Automatic per-location timezone resolution requires setting the
 1407: C<TIMEZONEDB_KEY> environment variable to a valid key from
 1408: L<https://timezonedb.com>.
 1409: Without it the module defaults to C<Europe/London> for all locations.
 1410: 
 1411: =item * No list-context support
 1412: 
 1413: C<weather()> and C<forecast()> enforce scalar/hashref context via
 1414: L<Return::Set>.
 1415: List context is not currently supported.
 1416: 
 1417: =item * Access control is enforced, but only by convention for subclasses
 1418: 
 1419: Helper functions with no need of an object (coordinate and URL handling, retry
 1420: arithmetic) are L<Sub::Private> and cannot be called, overridden or mocked from
 1421: outside this file.
 1422: Helper methods that need the object are L<Sub::Protected>: callable from this
 1423: class and its subclasses but not from unrelated code.
 1424: White-box tests therefore have to go through the public methods or subclass
 1425: C<Weather::Meteo>.
 1426: 
 1427: Both modules switch their checks off when C<$ENV{HARNESS_ACTIVE}> is set,
 1428: which C<prove> and C<make test> do, so under a test harness the helpers can be
 1429: called from anywhere.
 1430: Set C<$Sub::Private::config{harness_bypass}> and
 1431: C<$Sub::Protected::config{harness_bypass}> to C<0> to test the enforcement
 1432: itself, as F<t/i18n.t> does.
 1433: Also note that L<Sub::Protected> registers the C<:Protected> attribute in
 1434: C<UNIVERSAL>, so it is available to every package in the process once this
 1435: module is loaded.
 1436: The cost of this strictness is that a subclass can reuse the protected methods
 1437: but not the private functions, so it cannot change, for example, how URLs are built.
 1438: 
 1439: =item * Errors are reported as C<undef> plus a warning
 1440: 
 1441: Every failure of C<weather()>, C<forecast()> and C<sunrise_sunset()> that is not
 1442: a usage error comes back as C<undef> with a C<carp>.
 1443: A caller therefore cannot tell a rate limit from an outage from an unknown
 1444: place without parsing the warning text.
 1445: This is the documented contract, kept for compatibility, but an exception
 1446: class (or at least a C<last_error()> accessor) would be a better design.
 1447: 
 1448: =item * Retries block the caller
 1449: 
 1450: Retrying a transient failure sleeps in the calling process, for up to
 1451: C<max_retries> times the (doubling, capped) delay: about 7 seconds with the
 1452: defaults.
 1453: Set C<max_retries> to C<0> for a non-blocking client, or do the retrying
 1454: yourself.
 1455: 
 1456: =item * Messages are translatable, but the plural rules are not
 1457: 
 1458: L</i18n> understands C<one> and C<other> only, which is right for English,
 1459: German and French but not for languages with several plural forms.
 1460: It also does not translate strings that come from outside the module, such as
 1461: the text of an HTTP status line or an exception from the JSON decoder.
 1462: 
 1463: =item * Dates are checked by shape, not by calendar
 1464: 
 1465: C<2022-02-31> and C<2022-13-45> have the shape C<YYYY-MM-DD> and are passed to
 1466: the API, which rejects them.
 1467: The module does not check them itself because no calendar module is a
 1468: dependency.
 1469: 
 1470: =item * "Today" is the host's date, not the location's
 1471: 
 1472: When C<sunrise_sunset()> is called without a date, or with today's date, "today"
 1473: is taken from the local clock of the machine running the code, not from the
 1474: C<tz> requested.
 1475: Near midnight and for distant time zones that can be a day out.
 1476: 
 1477: =item * Cache keys use the text of the coordinates
 1478: 
 1479: C<51.34> and C<51.340> are cached separately, and so are C<tz> spellings that
 1480: the API treats as the same zone.
 1481: The results are correct; only the hit rate suffers.
 1482: 
 1483: =item * Host parameter restricted to plain DNS hostnames
 1484: 
 1485: The C<host> constructor parameter (and the C<WEATHER__METEO__host> environment
 1486: variable) must match C</\A[A-Za-z0-9][A-Za-z0-9.\-]*(:\d{1,5})?\z/>.
 1487: IP addresses in CIDR notation, URLs with path components, C<@>-style
 1488: user-info, and other special characters are rejected with a C<croak> to
 1489: prevent Server-Side Request Forgery.
 1490: If you need to test against a local service on a non-standard port, use a
 1491: plain C<hostname:port> string (e.g. C<localhost:8080>).
 1492: 
 1493: =item * Coordinate values limited to decimal numbers
 1494: 
 1495: Latitude and longitude must match C</\A-?(?>\d+)(?:\.(?>\d+))?\z/> after
 1496: leading-decimal normalisation.
 1497: Exponential notation (C<1.5e2>), hex (C<0x1F>), and strings with embedded
 1498: whitespace are rejected.
 1499: Pass a pre-formatted decimal string rather than a Perl numeric expression if
 1500: your caller might produce non-decimal representations.
